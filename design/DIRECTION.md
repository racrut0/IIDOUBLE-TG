# IIDouble — визуальное направление

Продукт: личный цифровой двойник в Telegram. Главная работа интерфейса — дать
поговорить с двойником, затем уточнить его реакцию и память. Переписка находится
в центре композиции; инструменты развития доступны рядом.

## Палитра

| Токен | Цвет | Роль |
| --- | --- | --- |
| Графит | `#1E1F28` | Фон рабочего пространства |
| Поверхность | `#282A36` | Навигация, поля, вторичные области |
| Контур | `#3B3D4E` | Границы и разделение контролов |
| Светлый текст | `#F0F1F7` | Основной текст |
| Лаванда | `#B7BDF8` | Двойник, основное действие, выбор |
| Небесный | `#8AADF4` | Сообщения собеседника, второй контур знака |

Служебный зелёно-мятный используется только для бесплатных операций и статуса,
красный — для ошибки и удаления. Текст на светлой акцентной кнопке — тёмный.

Референсы: [Catppuccin Macchiato](https://catppuccin.com/palette/#macchiato)
для двух акцентов и [Radix](https://www.radix-ui.com/colors/docs/palette-composition/composing-a-palette)
для спокойных нейтральных поверхностей и смыслового назначения оттенков.
Это адаптация для приложения, а не копирование готовой темы.

## Типографика

Onest, локально размещённый вариативный шрифт с кириллицей; 400 — основной текст,
500 — элементы управления, 600 — заголовки, 700 — название. Рабочая шкала:
12 / 14 / 16 / 20 / 28 / 40 px. Длинные строки ограничены 68 символами.
Источник: [Google Fonts](https://github.com/google/fonts/tree/main/ofl/onest).
Лицензия хранится вместе со шрифтом.

## Два варианта компоновки

Вариант A: постоянная боковая навигация, диалог в центре, справа краткая подсказка.
Контент выровнен по левому краю; пустой диалог может иметь центрированное приглашение.

```text
┌───────────────┬────────────────────────────┬──────────────────┐
│ IIDouble      │ Диалог       Собеседник    │                  │
│               ├────────────────────────────┤ Твоя манера      │
│ Общение       │                            │                  │
│ Развитие      │      две реплики           │ Переписки        │
│ Память        │      человек ↔ двойник     │ Реакции          │
│               │                            │ Проверка         │
│ Бюджет        │ Сообщение …      Отправить │                  │
└───────────────┴────────────────────────────┴──────────────────┘
```

Вариант B: весь экран занимает диалог, инструменты находятся в раскрывающемся меню.

```text
┌────────────────────────────────────────────┐
│ IIDouble                            Меню   │
│                                            │
│                  Диалог                    │
│                                            │
│ Сообщение …                    Отправить   │
└────────────────────────────────────────────┘
```

Выбран A для компьютера; B — основа мобильного варианта с нижней навигацией.
Это сохраняет доступ к разным способам обучения, не отодвигая поле сообщения вниз.

## Проверка направления до реализации

Первый эскиз с одинаковыми плитками инструментов заменён боковой навигацией:
действия имеют разную частоту использования, а диалогу нужно собственное пространство.
Декоративная карточка с процентом похожести заменена понятной подсказкой и переходом
к настоящей проверке: достоверная оценка появляется только после оценок владельца.
Характерный элемент один — две смещённые реплики. Градиенты, декоративные графики,
вымышленные сообщения и показатели в рабочий интерфейс не добавляются.

## Принципы реализации

- Сохранить существующие действия API, бюджет и привязку оценок к ответу.
- Показывать только настоящие сообщения и полученные от сервера показатели.
- Сначала диалог; формы обучения — отдельные спокойные экраны.
- Названия действий и подтверждений согласовать на русском языке.
- На мобильном оставить доступными диалог, собеседников и память.
- Поддержать клавиатуру, заметный фокус, контраст и уменьшение анимации.
- Проверять экраны с искусственными данными и подменой модели.

## Проверка реализации

Просмотрены настольный экран 1280 × 720 и мобильные 390 × 844 и 320 × 720.
После первого просмотра укорочена навигация, второстепенные инструменты перенесены
в раскрывающийся список, устранена лишняя прокрутка пустого диалога.
Повторяющиеся ответы сервера над заполненными формами убраны.
Мобильное меню ограничивает фокус своей областью, закрывается по Escape и при выборе
раздела; фон на время открытия недоступен для взаимодействия. Для клавиатуры выделен
контур поля сообщения. При уменьшении анимации переходы отключаются.

В браузере проверены потоковый ответ, исправление, следующий ход диалога, переключение
собеседника, тренировка, предпросмотр импорта, сравнение ответов и раздел памяти.
Проверки используют искусственные сообщения, отдельную базу и подменённый API модели.

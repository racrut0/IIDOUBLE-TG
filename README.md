# ИИ-двойник в Telegram

Telegram-бот и Mini App, которые отвечают в манере владельца на основе его профиля,
реальных диалогов, Q&A и подтверждённых исправлений.

## Что изменилось

- Память хранится в SQLite: полный архив отделён от короткого контекста модели.
- Старые `memory/<telegram_id>.json` автоматически импортируются при первом обращении.
  Оригиналы остаются на месте. Повреждённый JSON вызывает ошибку, а не тихий сброс.
- Из импорта формируются пары «сообщение собеседника → ответ владельца».
  JSON-экспорт сохраняет Telegram id, даты и явные связи ответов.
- Обычный чат не обучает профиль. Обучение происходит через Q&A, импорт и оценки.
- Постоянные правила передаются в каждом запросе, независимо от совпадения слов.
- Запрос содержит отдельные инструкции и сообщения с ролями. Бюджет контекста по умолчанию —
  3500 оценочных входных токенов; слишком длинные обязательные правила и ввод отклоняются явно.
- Поиск примеров работает локально: SQLite FTS5, нормализация русских окончаний и несколько
  групп бытовых намерений. Это лексический поиск, не embeddings и не семантическая модель.
- Mini App показывает текст по мере получения. Незавершённый ответ не сохраняется как диалог.
- Исправление заменяет неправильный ответ в недавней истории и сохраняется как один пример.
- Сохраняются фактические токены API, кешированные токены, время до первого фрагмента
  и полное время запроса. Тексты переписки в таблицу метрик не записываются.
- Параллельные изменения записываются отдельно. Для одного владельца одновременно
  готовится один ответ; разные владельцы могут обслуживаться параллельно.
- Backend всегда проверяет подпись Telegram. Обход через `WEBAPP_DEV_USER_ID` удалён.

## Установка и запуск

Python 3.11 или новее. В Windows PowerShell из папки проекта:

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item config.example.json config.json
```

В `config.json` укажи свои `TG_TOKEN`, `OPENAI_API_KEY`, `WEBAPP_URL` и `WEBAPP_API_URL`.
Для первого запуска бота достаточно двух ключей: `TG_TOKEN` из @BotFather и
`OPENAI_API_KEY` из кабинета OpenAI API. Поля `WEBAPP_URL` и `WEBAPP_API_URL`
можно оставить пустыми до размещения Mini App и backend на HTTPS-хостинге.
Секреты можно хранить в `.env` или переменных окружения; окружение имеет приоритет.
Настоящие ключи не следует добавлять в репозиторий.

В репозиторий входит только `config.example.json` с заглушками вместо ключей.
Локальные настройки, варианты `.env`, базы памяти, переписки, логи, резервные копии,
временные файлы и отчёты о компьютере исключены через `.gitignore`.

```powershell
.\.venv\Scripts\python.exe bot.py
```

В другом терминале запусти backend:

```powershell
.\.venv\Scripts\python.exe -m uvicorn web_backend:app --host 127.0.0.1 --port 8000
```

Размести `index.html` на HTTPS-хостинге, например GitHub Pages. Backend также должен быть
доступен через HTTPS. Его адрес передаётся Mini App ботом в параметре `api`.
Без настроенного адреса приложение показывает понятное сообщение и не отправляет данные
на старый тестовый сервер. CORS по умолчанию разрешает только origin из `WEBAPP_URL`.
Дополнительные origin задаются через переменную окружения `WEBAPP_ORIGINS` через запятую.

Пример `.env`:

```dotenv
TG_TOKEN=your_telegram_bot_token
OPENAI_API_KEY=your_openai_api_key
OPENAI_MODEL=gpt-6.1-terra
WEBAPP_URL=https://your-name.github.io/IIDOUBLE-TG/
WEBAPP_API_URL=https://your-api.example
MEMORY_DB_PATH=memory/twin.sqlite3
CONTEXT_TOKEN_BUDGET=3500
MAX_OUTPUT_TOKENS=400
WEBAPP_VERSION=12
```

Модель настраивается через `OPENAI_MODEL`; доступность выбранной модели нужно проверить
в своём аккаунте. Локальные проверки не требуют ключей и не вызывают API.
Для `gpt-6.1-terra` и `gpt-6-luna` адаптер автоматически задаёт
`reasoning.effort=none`, чтобы бюджет короткого ответа не расходовался на рассуждения.

## Как обучать

1. Пройди анкету в боте и добавь постоянные правила через Mini App или
   `/remember стиль пиши со строчной буквы, редко используй эмодзи`.
2. Импортируй свой чат. Предпочтителен JSON-экспорт Telegram Desktop без медиа.
   В Mini App можно указать своё имя в экспорте. В боте можно прислать файл
   `.json`, `.html`, `.txt` до 15 МБ или использовать `/import_chat текст переписки`.
3. Добавляй реальные ситуации в Q&A: сообщение собеседника и свой ответ.
4. Оценивай ответы. Кнопка «Не похоже» позволяет записать правильный вариант.

### Персональные вопросы о жизни

Кнопка «Сгенерировать вопрос» выбирает известную деталь из анкеты, фактов, предпочтений,
событий дня, Q&A или собственных сообщений владельца из импорта. Нейросеть через API
формулирует вопрос об этой детали. Правила выбора темы и сохранение прогресса работают локально.

После сохранения ответа следующий вопрос уточняет именно его, а затем помогает понять
привычную реакцию или решение. После двух уточнений генератор переключается на другую
известную тему, если она есть. Например: свой проект → что в нём сложно → конкретный случай
→ как человек поступает в такой ситуации. Это направление интервью, а не готовый список вопросов.

При пустой памяти задаётся открытый вопрос для знакомства. Сведения о работе, семье и
событиях нельзя придумывать. Отказ обсуждать тему откладывает её; добровольный ручной Q&A
по этой теме позволяет к ней вернуться. Ответы на гипотетические ситуации не считаются
доказательством реальной биографии.

Заданные вопросы и связи с ответами сохраняются в SQLite и учитываются после перезапуска.
Повторы проверяются также среди старых записей; формулировки недавних вопросов дополнительно
сравниваются по словам и сходству текста. Вопрос без связи с выбранной новой темой, повтор
или неверный формат повторно запрашивается один раз. После двух неудачных попыток выводится
сообщение об ошибке; прогресс и память не меняются. Уточнения могут использовать местоимения.

На одну генерацию обычно приходится один запрос API, максимум два при отклонённом результате.
Объём запроса ограничен общим бюджетом и 2400 оценочными входными токенами.
Оценка сходства слов не является полной семантической проверкой: качество формулировок
и правильность понимания жизненных обстоятельств нужно проверять на реальных ответах владельца.

Фразы без автора сохраняются в архив, но не используются как ответы владельца.
При наличии Telegram id он имеет приоритет перед совпадением имени.
Повторный импорт JSON одного чата обновляет записи без дубликатов.
Для TXT/HTML идентичность определяется участниками и положением сообщения;
для нескольких однотипных чатов надёжнее JSON с id чата.

Описание «Как я сегодня отвечал» действует на текущий и предыдущий день.
Статистическое описание манеры вычисляется локально, без дополнительного вызова модели.
Старые разговоры остаются в архиве; для продолжения используется недавняя история
и короткая локальная выдержка. Выдержка не заменяет долговременные факты владельца.

Команды: `/start`, `/memory`, `/profile`, `/facts`, `/preferences`, `/style`,
`/remember`, `/forget`, `/search_memory`, `/import_chat`, `/reset`.
Удаление импортированного чата убирает его архив, примеры и извлечённые сведения.
`/reset` очищает активную память пользователя; старый JSON не импортируется повторно.
Исходный JSON после миграции остаётся резервной копией и не удаляется автоматически.

## Проверки и оценка сходства

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest -q --basetemp=work/pytest-local
.\.venv\Scripts\python.exe evaluate.py --dataset evaluation/dataset.example.json --responses evaluation/responses.example.json
```

Тесты используют временную БД и подмену модели. Они проверяют путь данных, импорт,
границы контекста, миграцию, параллельную запись, подпись Telegram и потоковый API.
Примеры в `evaluation/` искусственные: это образец формата, а не оценка твоего стиля.

Для реальной проверки подготовь 50–100 ситуаций из отдельных диалогов, которые **не
импортированы в обучение**. Укажи `id`, `chat_id`, `context`, `expected_answer`.
Сначала можно сравнить готовые ответы через `--responses` без запросов к API.
Для генерации требуется явный флаг `--live`; этот режим расходует API-токены:

```powershell
.\.venv\Scripts\python.exe evaluate.py --dataset work/held-out.json --user-id YOUR_TELEGRAM_ID --live --output work/evaluation.json
```

Проверка отклоняет известные id диалогов из обучающего архива. Ответы из тестового набора
не добавляются в запрос и память. При ручном копировании тех же реплик в Q&A источник
не всегда можно определить автоматически — такие пересечения нужно исключить при подготовке набора.
Длина и пересечение слов в отчёте — вспомогательные показатели. Поле `owner_rating`
заполняет владелец после чтения ответов. Дообучение весов модели в этот проект не включено.

## Файлы и резервные копии

- `bot.py` — Telegram-интерфейс и парсеры импорта.
- `web_backend.py` — подписанные запросы Mini App и потоковый endpoint.
- `services.py` — общие операции общения и обучения.
- `personalization.py`, `retrieval.py` — профиль, поиск примеров и бюджет запроса.
- `questions.py` — выбор личной темы, последовательные уточнения и проверка вопросов.
- `storage.py` — SQLite, миграция, архивы, метрики и защита записи.
- `llm.py` — единственный адаптер модели.
- `evaluate.py` — локальная и явная API-оценка.

База по умолчанию: `memory/twin.sqlite3`, путь считается относительно проекта.
При резервном копировании работающей базы используй SQLite backup API; простое копирование
только `.sqlite3` при включённом WAL может пропустить последние изменения.
Для переноса памяти перенеси БД с корректной резервной копией; JSON нужен только для первоначальной миграции.

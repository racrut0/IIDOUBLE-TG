# ИИ-двойник в Telegram

Telegram-бот и Mini App, которые отвечают в манере владельца на основе его профиля,
реальных диалогов, Q&A и подтверждённых исправлений.

## Что изменилось

- Память хранится в SQLite: полный архив отделён от короткого контекста модели.
- Старые `memory/<telegram_id>.json` автоматически импортируются при первом обращении.
  Оригиналы остаются на месте. Повреждённый JSON вызывает ошибку, а не тихий сброс.
- Из импорта формируются пары «сообщение собеседника → ответ владельца».
  JSON-экспорт сохраняет Telegram id, даты и явные связи ответов.
- Обычный чат не обучает профиль. Обучение происходит через Q&A, импорт и оценки.
- Постоянные правила передаются в каждом запросе, независимо от совпадения слов.
- Запрос содержит отдельные инструкции и сообщения с ролями. Бюджет контекста по умолчанию —
  2200 оценочных входных токенов; слишком длинные обязательные правила и ввод отклоняются явно.
- Поиск примеров работает локально: SQLite FTS5, нормализация русских окончаний, группы
  бытовых ситуаций и приоритет подходящих исправлений. Это лексический поиск с правилами,
  не embeddings и не семантическая модель.
- Mini App показывает текст по мере получения. Незавершённый ответ не сохраняется как диалог.
- Исправление заменяет неправильный ответ в недавней истории и сохраняется как один пример.
- Собеседники задаются владельцем: тип отношений, пожелания и связанные переписки.
  У каждого своя история; примеры и исправления других собеседников исключаются.
- Проверка сходства сохраняет 20 постоянных ситуаций из одного чата и сравнивает прогоны
  по оценкам владельца. Подготовка, просмотр и оценки не используют API.
- Сохраняются фактические токены API, кешированные токены, время до первого фрагмента
  и полное время запроса. Тексты переписки в таблицу метрик не записываются.
- Параллельные изменения записываются отдельно. Для одного владельца одновременно
  готовится один ответ; разные владельцы могут обслуживаться параллельно.
- Backend всегда проверяет подпись Telegram. Обход через `WEBAPP_DEV_USER_ID` удалён.

## Установка и запуск

Python 3.11 или новее. В Windows PowerShell из папки проекта:

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item config.example.json config.json
```

В `config.json` укажи свои `TG_TOKEN`, `OPENAI_API_KEY`, `WEBAPP_URL` и `WEBAPP_API_URL`.
Для первого запуска бота достаточно двух ключей: `TG_TOKEN` из @BotFather и
`OPENAI_API_KEY` из кабинета OpenAI API. Поля `WEBAPP_URL` и `WEBAPP_API_URL`
можно оставить пустыми до размещения Mini App и backend на HTTPS-хостинге.
Секреты можно хранить в `.env` или переменных окружения; окружение имеет приоритет.
Настоящие ключи не следует добавлять в репозиторий.

В репозиторий входит только `config.example.json` с заглушками вместо ключей.
Локальные настройки, варианты `.env`, базы памяти, переписки, логи, резервные копии,
временные файлы и отчёты о компьютере исключены через `.gitignore`.

### Запуск вместе с Mini App на Windows

Если ключи и зависимости уже настроены, закрой прежнее окно с `bot.py` и открой
**`Start Mini App.cmd`** в папке проекта. Он сам запускает настоящий бот, интерфейс
и временный HTTPS-адрес. Когда появится «Бот запущен», отправь боту `/start`, нажми
«Mini App», затем **«Открыть Mini App» под сообщением бота**. Вручную вставлять адреса
для этого режима не нужно.
Ту же кнопку можно получить командой `/miniapp`.

Кнопка под сообщением нужна для входа: Telegram передаёт ей подписанные данные
пользователя. Прямой запуск Mini App из нижней клавиатуры не предоставляет этих данных
([документация](https://core.telegram.org/bots/webapps#webappinitdata)). При пустых данных
входа интерфейс показывает инструкцию и не отправляет запросы к API; серверная проверка
подписи остаётся обязательной. Обычная ссылка в браузере не даёт доступа к памяти.

При первом запуске скачивается официальный Cloudflare Tunnel с проверкой SHA-256.
Используется [Quick Tunnel](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/)
для тестирования без домена и регистрации. Адрес меняется при новом запуске;
после перезапуска снова отправь `/start`, чтобы получить актуальную кнопку.
Оставляй окно запуска открытым. Ctrl+C останавливает только запущенные им процессы.
Закрытие окна или выключение компьютера прерывает доступ.

Настройки HTTPS передаются дочерним процессам через окружение. Файлы с ключами и
постоянными адресами не перезаписываются. Используются настоящая память и действующие
ограничения расходов; запуск и проверка подключения не обращаются к модели.
Генерация ответов в таком Mini App использует обычный API модели.
Интерфейс и API доступны с одного адреса; приватные файлы сервер не раздаёт.
Память по-прежнему доступна только по подписанным данным Telegram.

Дополнительная проверка HTTPS и защиты, без запуска бота и запросов к модели:

```powershell
.\.venv\Scripts\python.exe run_miniapp.py --check-only
```

### Обычный запуск и постоянный хостинг

Для запуска только Telegram-бота:

```powershell
.\.venv\Scripts\python.exe bot.py
```

В другом терминале запусти backend:

```powershell
.\.venv\Scripts\python.exe -m uvicorn web_backend:app --host 127.0.0.1 --port 8000
```

Для постоянного размещения можно направить один HTTPS-адрес на `web_backend:app`:
он обслуживает интерфейс, публичные стили и API. Тогда `WEBAPP_URL` и `WEBAPP_API_URL`
содержат этот же адрес. Также можно разместить `index.html` вместе с папкой `assets/`
на отдельном HTTPS-хостинге, например GitHub Pages, и указать отдельный HTTPS-адрес API.
Адрес API передаётся Mini App ботом в параметре `api`.
Без настроенного адреса приложение показывает понятное сообщение и не отправляет данные
на старый тестовый сервер. CORS по умолчанию разрешает только origin из `WEBAPP_URL`.
Дополнительные origin задаются через переменную окружения `WEBAPP_ORIGINS` через запятую.

## Оформление Mini App

Тёмная графитовая палитра с лавандовыми и голубыми акцентами основана на
[Catppuccin Macchiato](https://catppuccin.com/palette/#macchiato) и принципах
[Radix Colors](https://www.radix-ui.com/colors/docs/palette-composition/composing-a-palette).
На компьютере диалог расположен рядом с навигацией и инструментами развития;
на телефоне доступны нижняя навигация и раскрывающееся меню.

Стили находятся в `assets/app.css`. Шрифт Onest с кириллицей загружается из
`assets/fonts/`, без обращения к внешнему сервису шрифтов; его лицензия — в `OFL.txt`.
При обновлении статического сайта публикуй всю папку `assets/` вместе с `index.html`.
Оформление не обращается к модели; сообщения и счётчики берутся из существующего backend.
Палитра, компоновка и обоснование решений описаны в [направлении дизайна](design/DIRECTION.md).

## Пример настроек

Пример `.env`:

```dotenv
TG_TOKEN=your_telegram_bot_token
OPENAI_API_KEY=your_openai_api_key
OPENAI_MODEL=gpt-6-luna
WEBAPP_URL=https://your-name.github.io/IIDOUBLE-TG/
WEBAPP_API_URL=https://your-api.example
MEMORY_DB_PATH=memory/twin.sqlite3
CONTEXT_TOKEN_BUDGET=2200
MAX_OUTPUT_TOKENS=240
API_BUDGET_USD=4.0
API_DAILY_BUDGET_USD=0.5
API_DAILY_REQUEST_LIMIT=200
API_USER_DAILY_REQUEST_LIMIT=100
WEBAPP_VERSION=12
```

Модель настраивается через `OPENAI_MODEL`; доступность выбранной модели нужно проверить
в своём аккаунте. Локальные проверки не требуют ключей и не вызывают API.
Для `gpt-6.1-terra` и `gpt-6-luna` адаптер автоматически задаёт
`reasoning.effort=none`, чтобы бюджет короткого ответа не расходовался на рассуждения.

## Режим для бюджета $5

По умолчанию используется `gpt-6-luna`, вход ограничен 2200 оценочными токенами,
выход — 240 токенами, включая возможные невидимые токены. До каждого обращения к API
адаптер резервирует максимальную оценочную стоимость в общей SQLite-базе.
Лимит приложения — **$4 за всё время**, ещё $1 из исходных $5 оставлен как запас.
Дополнительно действуют $0.50, 200 попыток суммарно и 100 на пользователя за последние 24 часа.
Окружение и `.env` могут переопределять значения из JSON, как и остальные настройки.

Общий счётчик охватывает бот, Mini App, генерацию вопросов и `evaluate.py --live`.
Он сохраняется при перезапуске, параллельных запросах и `/reset`; сброс памяти не возвращает
потраченные средства. Хранится таблица `api_spending` в той же базе. Не удаляй и не заменяй
саму базу, если нужно сохранить этот учёт. Все процессы должны использовать одну базу.

При резервировании используется консервативная оценка входа по UTF-8 и верхняя цена
входных токенов с запасом. После ответа резерв заменяется стоимостью по `usage`, с
10% надбавкой для запаса. Учитываются обычный вход, чтение кеша, запись кеша и выход.
Если часть статистики отсутствует, расход считается по более дорогому варианту.
При обрыве без статистики весь резерв остаётся израсходованным в местном счётчике.
Неожиданная модель, тариф или некорректные счётчики останавливают платные обращения
до проверки. Прозрачные отказы API до генерации снимают денежный резерв, но учитываются
в числе попыток. Автоматические повторы SDK отключены. Платные инструменты не подключаются.

Режим обработки задан явно как Standard (`service_tier=default`), рассуждения отключены,
кеш выбирает обычное время 30 минут. Проверенные тарифы на 02.11.2026:
[Luna](https://developers.openai.com/api/docs/models/gpt-6-luna) — $0.10 за миллион входных,
$0.01 кешированных, $0.125 записываемых в кеш, $0.50 выходных токенов;
[Terra](https://developers.openai.com/api/docs/models/gpt-6.1-terra) — $1, $0.05, $1.25 и $5 соответственно.
Другая модель блокируется до добавления проверенного тарифа в `spending.py`.

Кнопка «Бюджет API» показывает **местный учёт с момента включения защиты**, а не баланс
OpenAI. Уже совершённые ранее запросы, другие приложения с тем же ключом, налоги и изменение
тарифов не могут быть точно учтены этим счётчиком. Поэтому он не обещает общий расход
аккаунта строго до $5. Для дополнительной защиты настрой отдельный проект и его
[жёсткий лимит расходов](https://developers.openai.com/api/docs/guides/spend-limits)
в кабинете OpenAI; само OpenAI предупреждает о возможной задержке срабатывания.

Анкета, импорт, сохранение ответов, исправления, просмотр и управление памятью,
сессия «Научи отвечать как я» и автоматические тесты **не вызывают платный API**.
Генерация текста ответа, персонального вопроса и отдельного ответа в проверке сходства вызывает API.

## Как обучать

1. Пройди анкету в боте и добавь постоянные правила через Mini App или
   `/remember стиль пиши со строчной буквы, редко используй эмодзи`.
2. Импортируй свой чат. Предпочтителен JSON-экспорт Telegram Desktop без медиа.
   Сначала проверь автора и примеры в предпросмотре, затем подтверди сохранение.
   В Mini App можно указать своё имя в экспорте как подсказку. В боте можно прислать файл
   `.json`, `.html`, `.txt` до 15 МБ или использовать `/import_chat текст переписки`.
3. Добавляй реальные ситуации в Q&A: сообщение собеседника и свой ответ.
4. Оценивай ответы. Кнопка «Не похоже» позволяет записать правильный вариант.

### Предпросмотр импорта

Загрузка в боте и действие `import_tg_chat` в Mini App сначала создают отдельный
предпросмотр. До подтверждения ни сообщения, ни извлечённые факты, ни примеры из нового
файла не участвуют в ответах двойника, вопросах о жизни и тренировках.

Предпросмотр показывает имя файла, формат, найденных участников, количество твоих
сообщений и пар ответов. До трёх примеров из начала, середины и конца переписки помогают
проверить, чьи ответы будут использованы. При отсутствии пар показываются отдельные
сообщения выбранного автора. Пересланные сообщения исключаются из обучения; для HTML
проверяется отметка пересылки, вложенное имя автора пересылки не заменяет владельца сообщения.

Если в JSON есть `from_id`, он сравнивается с числовым Telegram ID загрузившего файл.
Имя или ник не позволяют выбрать сообщения с ID другого аккаунта как свои. Изменения
имени при одном ID объединяются в одного участника. Если в файле указаны только ID
других аккаунтов, переписку можно сохранить только как архив, без примеров для обучения.

Для HTML/TXT и записей без ID доступен выбор по имени. Это ручное подтверждение,
а не доказательство личности: одинаковые имена в исходном файле могут быть неразличимы.
Поэтому перед сохранением нужно проверить примеры. Поле имени в Mini App лишь помогает
предложить участника; окончательное решение принимается кнопкой подтверждения.

В Telegram после загрузки файла выбери свой номер из списка при необходимости, затем
нажми «Подтвердить импорт», «Только архив» или «Отменить импорт».
Команда `/import_chat` без текста позволяет вернуться к текущему предпросмотру.
В Mini App используй «Предпросмотр файла»/«Предпросмотр текста», список «Кто ты в этой
переписке» и кнопки подтверждения. При изменении автора примеры и счётчики обновляются.
Подтверждение старого выбора, чужого предпросмотра или уже обработанного файла отклоняется.

Предпросмотр хранится в отдельной таблице `pending_imports` той же локальной базы,
один на пользователя, и доступен после перезапуска в течение 24 часов. Новый файл
заменяет предыдущий неподтверждённый предпросмотр. Отмена удаляет его, не затрагивая
ранее сохранённую память. `/reset` также удаляет предпросмотр. Истёкшие записи удаляются
при обращении к ним или подготовке следующей загрузки. Сохранение архива и погашение
предпросмотра выполняются одной транзакцией: сбой записи не оставляет частичный импорт.

Одна загрузка ограничена 15 МБ, 100000 текстовых сообщений и 200 участниками.
Поддерживается экспорт отдельного чата. Предпросмотр, выбор автора, подтверждение,
отмена и повторный импорт не вызывают OpenAI API.

### Научи отвечать как я — бесплатно

Кнопка в боте и Mini App запускает семь ситуаций. Если есть переписка, до двух карточек
содержат реальные сообщения собеседника; сохранённый ответ владельца заранее не показывается.
Остальные — локальные упражнения на поддержку, отказ, границы, уточнение, радость,
несогласие и юмор. Они могут ссылаться на известную деталь жизни и всегда подписаны как
условные. Формулировки этих упражнений составлены в коде; отдельного запроса к модели нет.

Напиши текст своего ответа или пропусти карточку. Сессия возобновляется после перезапуска.
Повторное сохранение старой карточки отклоняется. Ответы хранятся в `reaction_examples`
и участвуют в подборе примеров для двойника. Биографические факты из тренировочных
ответов автоматически не извлекаются. Это подбор примеров в контекст, не дообучение весов.

### Почему ответ не похож

В Mini App при исправлении можно выбрать причину и пояснение. По умолчанию замечание
привязано к конкретной ситуации. Общее правило добавляется только при явном выборе
«Как общее правило моей речи». Для замечаний о тоне и выдуманных фактах отдельное
общее правило не выводится автоматически. Свой текст общего правила нужно указать явно.
В Telegram после исправления можно выбрать причину кнопкой; она действует для этой ситуации.

### Подбор реакции на ситуацию

Поиск сравнивает входящие ситуации, а не слова из ответов владельца. Кроме общих слов,
локальные признаки помогают найти поддержку, радость, просьбу о помощи, давление,
критику, уточнение или юмор. Примеры с явно противоположным исходом («сдал» и «не сдал»)
не подмешиваются друг к другу. Эти признаки описывают ситуацию собеседника и не задают
владельцу готовую «правильную» реакцию: в контекст попадает его реальный ответ.

Для коротких продолжений вроде «и что дальше?» при подборе учитывается предыдущее
содержательное сообщение собеседника. Новая явно сформулированная ситуация начинает
новый поиск. Сам вопрос при этом остаётся отдельным сообщением в истории.

Подходящее исправление владельца получает приоритет; сохранённый им неправильный вариант
исключается из альтернатив для этой ситуации. Для одной и той же формулировки используется
последнее исправление. Источник примера явно подписан в запросе модели. Ответы из Q&A
без связи с текущей ситуацией не используются как запасные примеры реакции.

Старые импортированные чаты получают обновлённый поисковый индекс автоматически при
запуске. Исходные сообщения, исправления и счётчик расходов сохраняются; повторная загрузка
экспортов не требуется. Обновление и подбор выполняются локально, дополнительных API-вызовов
нет. Общий лимит входа 2200 токенов и один вызов модели на ответ остаются прежними.
В метрики добавлены только количества примеров/исправлений и признак учёта предыстории,
без текстов личных сообщений.

Распознавание ситуаций ограничено словарём и правилами: ирония, сложные отрицания,
отношения с конкретным собеседником и необычные перефразировки могут распознаваться неверно.
Тесты проверяют механизм подбора; процент сходства ответов оценивает владелец на отдельных ситуациях.

### Собеседники и отношения

В Telegram открой «Собеседники» → «Добавить собеседника». В Mini App доступен экран
«Собеседники». Укажи название, тип отношений, свои пожелания и номера/флажки подтверждённых
чатов этого человека. Тип отношений выбирается вручную; программа не угадывает его по имени.
Новый профиль в Telegram сразу выбирается для общения, в Mini App нажми «Общаться с выбранным».

Профиль можно изменить, выбрать другой или вернуться к общей манере. Обычная история
хранится с `interlocutor_id`; переключение восстанавливает разговор выбранного человека,
включая историю, которая была вытеснена недавними разговорами с другими людьми.
Старые сообщения без этой метки остаются в общей манере. Исходные архивы сохраняются.
Для отдельного человека привязывай личные чаты: в групповом чате используются ситуации всей группы.

При выборе человека поиск читает только привязанные к нему импортированные примеры.
Новые ручные Q&A, тренировки и исправления помечаются выбранным собеседником и не
переносятся на других. Прежние общие подтверждённые примеры остаются общими; подходящее
исправление именно для выбранного человека имеет приоритет. Биографические сведения
о владельце и явно заданные общие правила сохраняют общий смысл.

Без привязанных чатов остаются пожелания и общие подтверждённые примеры. Тип «Друг» или
«Коллега» сам по себе не задаёт готовую вежливость, юмор или согласие: важны реальные ответы.
Сохранение, выбор и изменение собеседников работают локально. Дополнительных вызовов модели
нет, лимиты входа и выхода остаются прежними. Удаление профиля убирает настройки, сохраняя
исходные переписки и архив истории; его отдельные примеры не становятся общими автоматически.

### Постоянные 20 ситуаций

Открой «Проверка сходства» в Telegram или Mini App. Выбери подтверждённый чат либо
автоматический подбор и создай набор. Автоподбор предпочитает чат текущего собеседника,
если в нём достаточно подходящих ситуаций. Нужны 20 различных содержательных сообщений
собеседника и твоих ответов; ссылки без текста и чрезмерно длинные пары не подходят.
Набор сохраняется один раз и не меняется при повторном нажатии.

1. Подготовь прогон: это бесплатный расчёт запросов и максимального резерва на 20 ответов.
2. Для каждой ситуации нажми «Получить ответ · API». На одно нажатие — один вызов модели;
   автоматического запуска всего набора нет. Готовый ответ сохраняется и повторно не оплачивается.
3. Сравни ответ двойника со своим ответом в переписке и выбери «Похоже», «Частично» или
   «Не похоже». В Mini App можно добавить заметку. Оцени реакцию, а не дословное совпадение.
4. После изменений памяти или настроек подготовь новый прогон на тех же 20 ситуациях.
   Результаты предыдущих прогонов остаются для сравнения.

При подготовке из контекста исключается **весь исходный чат**: его примеры, извлечённые
сведения и связанные ответы. Совпадающие с проверочными ситуациями Q&A/исправления также
исключаются; старые истории и выдержки бесед не используются. Статистическое описание
манеры пересчитывается локально без исходного чата. Ожидаемые ответы находятся отдельно
от запросов и в модель не передаются. Для обычного общения исходный чат продолжает работать.
Это проверка переноса реакции на исключённые ситуации; совпадения сведений, вручную
скопированных в другие записи без источника, не всегда можно распознать.

Подготовленный прогон фиксирует запросы и настройки. Если обучающая память или параметры
модели изменились, незапущенные ответы требуют нового прогона. Оценки проверки не добавляют
тестовые ответы в обучение. «Похоже» = 1, «Частично» = 0.5, «Не похоже» = 0; процент — средняя
оценка **только оценённых** ситуаций. Рядом всегда указано их количество из 20. Частичные
прогоны не являются оценкой всего набора, а эти 20 ситуаций не доказывают сходство во всех диалогах.

Предел консервативного резерва одного прогона — **$0.05**, включая явные повторные попытки.
Общий и суточный счётчики приложения действуют дополнительно. Незавершённый ответ
не показывается как готовый; повтор нужно выбрать явно, максимум две попытки на ситуацию.
Прогон, ответы и оценки хранятся в отдельной таблице `evaluation_items` и не загружаются
в обычную память модели. `/reset` удаляет эти данные, сохраняя общий счётчик расходов.
Удаление исходного чата удаляет и его набор с прогонами.

### Управление сведениями

Mini App → «Управлять сведениями» показывает факты, предпочтения и жизненные ответы анкеты,
источник, известную дату и дату уточнения. Для старых записей дата может быть неизвестна.
Новые извлечённые сведения из Q&A сохраняют связь с исходным ответом в `owner_facts`.

Можно уточнить запись, отключить и снова включить её. Отключение сохраняет исходник в
локальном архиве, исключая точную нормализованную фразу и содержащие её записи из
контекста ответов, вопросов и упражнений, включая найденные примеры и недавнюю историю.
Это локальная текстовая фильтрация: смысловые перефразировки автоматически не распознаются.
Для удаления исходных данных используй существующее удаление записи или импортированного
чата. Возможные противоречия по месту жизни, имени и занятию отмечаются для проверки;
это подсказка, а не полная проверка фактов моделью.

В этом же экране можно закрывать и разрешать темы интервью. Явный запрет сохраняется,
в том числе после добровольного Q&A; он снимается кнопкой «Разрешить тему». Закрытые темы
исключаются из опорных записей и фона следующего вопроса, а также личных привязок упражнений.

### Персональные вопросы о жизни

Кнопка «Сгенерировать вопрос» выбирает известную деталь из анкеты, фактов, предпочтений,
событий дня, Q&A или собственных сообщений владельца из импорта. Нейросеть через API
формулирует вопрос об этой детали. Правила выбора темы и сохранение прогресса работают локально.

После сохранения ответа следующий вопрос уточняет именно его, а затем помогает понять
привычную реакцию или решение. После двух уточнений генератор переключается на другую
известную тему, если она есть. Например: свой проект → что в нём сложно → конкретный случай
→ как человек поступает в такой ситуации. Это направление интервью, а не готовый список вопросов.

При пустой памяти задаётся открытый вопрос для знакомства. Сведения о работе, семье и
событиях нельзя придумывать. Отказ обсуждать тему откладывает её; добровольный ручной Q&A
по этой теме позволяет к ней вернуться. Ответы на гипотетические ситуации не считаются
доказательством реальной биографии.

Заданные вопросы и связи с ответами сохраняются в SQLite и учитываются после перезапуска.
Повторы проверяются также среди старых записей; формулировки недавних вопросов дополнительно
сравниваются по словам и сходству текста. Вопрос без связи с выбранной новой темой, повтор
или неверный формат повторно запрашивается один раз. После двух неудачных попыток выводится
сообщение об ошибке; прогресс и память не меняются. Уточнения могут использовать местоимения.

На одну генерацию обычно приходится один запрос API, максимум два при отклонённом результате.
Объём запроса ограничен общим бюджетом и 2400 оценочными входными токенами.
Оценка сходства слов не является полной семантической проверкой: качество формулировок
и правильность понимания жизненных обстоятельств нужно проверять на реальных ответах владельца.

Фразы без автора сохраняются в архив, но не используются как ответы владельца.
При наличии Telegram id он имеет приоритет перед совпадением имени.
Повторный импорт JSON одного чата обновляет записи без дубликатов.
Для TXT/HTML идентичность определяется участниками и положением сообщения;
для нескольких однотипных чатов надёжнее JSON с id чата.

Описание «Как я сегодня отвечал» действует на текущий и предыдущий день.
Статистическое описание манеры вычисляется локально, без дополнительного вызова модели.
Старые разговоры остаются в архиве; для продолжения используется недавняя история
и короткая локальная выдержка. Выдержка не заменяет долговременные факты владельца.

Команды: `/start`, `/memory`, `/profile`, `/facts`, `/preferences`, `/style`,
`/remember`, `/forget`, `/search_memory`, `/import_chat`, `/reset`.
Удаление импортированного чата убирает его архив, примеры и извлечённые сведения.
`/reset` очищает активную память пользователя; старый JSON не импортируется повторно.
Исходный JSON после миграции остаётся резервной копией и не удаляется автоматически.

## Проверки и оценка сходства

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest -q --basetemp=work/pytest-local
.\.venv\Scripts\python.exe evaluate.py --dataset evaluation/dataset.example.json --responses evaluation/responses.example.json
```

Тесты используют временную БД и подмену модели. Они проверяют путь данных, импорт,
границы контекста, миграцию, параллельную запись, подпись Telegram и потоковый API.
Примеры в `evaluation/` искусственные: это образец формата, а не оценка твоего стиля.

Для первой реальной проверки подготовь до 20 ситуаций из отдельных диалогов, которые **не
импортированы в обучение**. Укажи `id`, `chat_id`, `context`, `expected_answer`.
Сначала можно сравнить готовые ответы через `--responses` без запросов к API.
Для генерации требуется явный флаг `--live`; этот режим расходует API-токены:

```powershell
.\.venv\Scripts\python.exe evaluate.py --dataset work/held-out.json --user-id YOUR_TELEGRAM_ID --live --output work/evaluation.json
```

Перед платной проверкой можно выполнить тот же запуск с `--plan` вместо `--live`:
он покажет резерв без API. По умолчанию один платный запуск ограничен 20 ситуациями
и резервом $0.05. Проверка всего набора выполняется до первого платного обращения.
Общий и суточный бюджеты приложения продолжают действовать на каждый запрос.
Параметры `--max-cases` и `--max-cost-usd` позволяют явно изменить ограничения проверки.

Проверка отклоняет известные id диалогов из обучающего архива. Ответы из тестового набора
не добавляются в запрос и память. При ручном копировании тех же реплик в Q&A источник
не всегда можно определить автоматически — такие пересечения нужно исключить при подготовке набора.
Длина и пересечение слов в отчёте — вспомогательные показатели. Поле `owner_rating`
заполняет владелец после чтения ответов. Дообучение весов модели в этот проект не включено.

## Файлы и резервные копии

- `bot.py` — Telegram-интерфейс и парсеры импорта.
- `web_backend.py` — публичный интерфейс, подписанные запросы Mini App и потоковый endpoint.
- `run_miniapp.py`, `Start Mini App.cmd` — совместный запуск Mini App и бота через временный HTTPS.
- `services.py` — общие операции общения и обучения.
- `personalization.py`, `retrieval.py` — профиль, поиск примеров и бюджет запроса.
- `questions.py` — выбор личной темы, последовательные уточнения и проверка вопросов.
- `imports.py` — участники, проверка автора и предпросмотр импорта.
- `training.py`, `owner_memory.py` — бесплатные упражнения и управляемые сведения.
- `interlocutors.py`, `telegram_workflows.py` — собеседники и новые Telegram-экраны.
- `benchmarks.py` — постоянные 20 ситуаций, подготовка, ограниченная генерация и оценки.
- `spending.py` — общий денежный резерв, лимиты и счётчик расходов.
- `storage.py` — SQLite, миграция, архивы, метрики и защита записи.
- `llm.py` — единственный адаптер модели.
- `evaluate.py` — локальная и явная API-оценка.

База по умолчанию: `memory/twin.sqlite3`, путь считается относительно проекта.
При резервном копировании работающей базы используй SQLite backup API; простое копирование
только `.sqlite3` при включённом WAL может пропустить последние изменения.
Для переноса памяти перенеси БД с корректной резервной копией; JSON нужен только для первоначальной миграции.
